# 请求、缓存与上下文整理

本机制参考 DeepSeek Harness 的 compaction，但按 Prism 的人物、时间与原话依据需求实现。入口是 `ContextOptimization.swift` 的 `OptimizedTurn`；正常发送与重新生成都使用它。它不替代时间轴确认、人物关联确认或安全判断。

## 保存与请求回放

- 用户原文和最终显示文本保持独立。每条用户消息可保存当轮的 `requestContext`、`requestHint`；后续按原样回放，不把新的时间或记忆重新插到旧消息上。
- 章节索引进入当前轮快照，不再放到整段历史前面每轮改写。客户端用排序稳定的 JSON 编码；同一服务商的工具定义集合、顺序在工具轮和最终合成轮保持一致，最后一轮通过 `tool_choice: none` 禁止继续调用。
- 每条助手消息可保存完整 `toolTranscript`、独立的最终 `wireReasoning` 和未去除首尾空白的 `wireContent`，避免用界面合并后的推理重建请求。原始工具结果为 `content`，较短的模型投影为 `projectedContent`。每份结果只作为一条对应的 tool 消息发送。
- 这些新增字段随会话写入现有 SQLite 集合，也随 JSON 快照导出；会话文件会比以前大。附件字节仍是当次请求的临时数据，不新增附件持久化承诺。旧会话缺少新字段时仍能加载，不能恢复它从未记录过的历史请求快照。

## 压力评估与预算

完整请求构造后估算消息、系统提示、工具定义、工具结果和输出预留。图像使用每张 16,384 token 的视觉预留，不把 base64 当普通文本计数；它仍是估算，不是服务端视觉计价。

默认可识别的官方 Flash/Pro 线路使用 1,000,000 的窗口，未识别或自定义线路从保守的 131,072 开始；设置里可按服务商实际能力填写，范围为 8,192–32,000,000。没有实现自动探测所有服务商的模型容量。

设窗口为 W、回复预留为 O：触发线为 `min(0.8 × W, W − O − min(65536, W/8))`，近期保留目标为 `(W − O) × 0.16`。这些不是原先固定的 55%/75%/85% 分档。若同一线路已报告的输入明显高于估算，后续会保守上调估算系数；不把缺失字段当成实测，也不把其他模型的系数直接套过来。

## 整理流程

1. 原始工具结果和当前快照先提交成功，再改变送给模型的投影。
2. 只有达到触发线或出现明确超限时才裁剪过长工具结果；超过 8,192 字符的结果保留前 4,096 与后 1,024 字符，并加入省略标记和来源 ID。使用 Swift 字符边界，不拆开扩展字形。完整原始结果保留在本地。
3. 重新测量；压力已经解除则不调用摘要模型。
4. 仍有压力时选取较早的完整对话轮次，当前用户消息保留，工具调用和结果作为同一助手消息内的完整子轮次处理。摘要调用固定关闭思考；同一轮最多两次摘要尝试，较大的旧历史分为能放入该线路窗口的完整前缀。
5. 摘要必须返回受限 JSON 条目，带原始消息 ID、逐字短引用和事实/助手假设/待解决问题分类。程序校验来源、引用、角色、长度与实际缩减量。它不能自动证明每个观点都被引用语义支持，因此真实模型仍需验收。
6. 来源指纹采用与 SQLite 日期精度一致的编码。新摘要只在来源仍一致、事务成功后启用。编辑、删除或顺序变化会使检查点失效；原始消息不被摘要覆盖。
7. `fetch_context` 可以按对话、消息、工具调用 ID 分页回查，默认 3,000、最多 6,000 字符，并标明是否还有下一页。来源缺失时不编造。两轮工具执行上限仍然有效：若预算已用尽，模型必须说明证据缺口。

明确的 `context_length_exceeded` / `context_window_exceeded` 才允许安全整理后重试；请求必须确实变短。每个模型请求最多重试一次，不重试普通 HTTP 400、不重跑已经开始输出的请求，也不重做已执行的工具副作用。无法缩小的单条当前消息/附件仍需用户缩短。

## 思考与后台开销

官方 DeepSeek 路线默认开启可关闭的“按任务自动调整思考”：第一阶段使用 low，普通问题可直接回答；模型需要深入分析时可调用 `request_deeper_analysis`，工具返回后的阶段采用用户设置的强度。自定义路线和关闭自动调整时保留用户固定设置。复杂性判断与升级是否恰当仍需真实模型检查。

本地人物、章节、记忆和原话查询不增加模型请求；官方搜索固定使用 Flash + Low（Messages API 的 `thinking.type: enabled` 和 `output_config.effort: low`），独立于主模型的思考开关和强度；搜索端初筛来源、标明原文/摘要/片段及证据冲突，主模型再综合判断。最多 5 次服务端搜索，4,096 输出 token 包括思考；达到输出上限或只有思考而无可用正文/来源时返回可读错误，不把未完成结果当作证据，也不自动重试。安全前置检查继续运行，不以缓存优化跳过；辅助整理请求也继续关闭思考。画像整理按原始用户消息、章节、语言、线路和重建版本校验输入，已成功处理且未变的内容不再重复调用，失败不标记为已处理。

## 数据与验证边界

设置页展示总输入、总输出、缓存率、服务商已报告的思考 token、后台/上下文摘要请求数，以及最近请求的估算与实测输入（若有）。思考 token 是输出的一部分，不再额外叠加进总输出。搜索接口使用 Messages API 的计数规则，将缓存读取计入总输入一次；缺少 usage 不编造。

确定性回归见 `ContextOptimizationTests.swift`，覆盖裁剪后免摘要、来源与否定引用、事务冲突、重启与回查、来源编辑/删除、取消、一次超限恢复、拒绝普通错误/部分输出重试、稳定回放与工具集合、参数适用范围、图像预留和 usage 统计。真实缓存命中、总费用、响应时间与摘要语义质量需要使用合成材料做真实 API 对照；本地/mock 通过不等于这些效果已经验收。
