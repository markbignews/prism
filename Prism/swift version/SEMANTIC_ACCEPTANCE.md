## 采集前四项的原始模型证据

`LiveAcceptanceTests` 使用真实 ChatAgent 与四条合成输入，在新建临时目录中运行，不读取已有用户设置和 Keychain。默认禁用；显式启用后会消费所配置服务的 API 额度。凭据只从环境读取，报告不写入凭据。

在 Mac 的本地终端安全设置 `PRISM_TEST_API_KEY` 后运行；不要将 Key 写进命令历史、仓库或报告：

```sh
cd "Prism/swift version"
PRISM_RUN_LIVE_ACCEPTANCE=1 swift test --filter LiveAcceptanceTests
```

可选环境变量：`PRISM_TEST_BASE_URL`、`PRISM_TEST_MODEL`、`PRISM_TEST_AUXILIARY_MODEL`。`PRISM_ACCEPTANCE_SCENARIOS=negation,current-danger` 可只复测指定场景。报告位置由测试输出给出，状态为 `awaiting-human-review` 或 `request-failed`，不会自动批准语义验收。其余八项含故障组合和 UI 操作，须在应用中逐条核对。

## 本轮新增工程手工验收

- 简中、繁中、英文分别触发归纳失败、附件类型/大小错误、章节详情与工具执行状态，检查显示及布局。
- 长会话输入、滚动、IME、停止、重新生成、切换会话，检查后台保存时的响应性。
- 真实 Keychain 新装、旧配置迁移、拒绝访问、解锁后重试、签名身份变化后的升级，以及移动数据目录。
- 写入失败后重试；冲突后导出、重新加载；退出保存失败时的三个原生选项。
- JSON 快照跨机器导入；每台机器重新设置自己的 API Key。临时目录的自动化往返不等于跨机器 UI 已验收。
- Developer ID 签名、公证、stapling 和干净 Mac 首次打开。无账号凭据时不宣称已完成。
- GitHub workflow 远端首次绿灯与必需状态检查。工作流文件的本地检查不代表远端已执行。

## 本轮真实样本记录

2026-10-15 使用 `deepseek-flash` 主/辅助模型，共采集 10 个合成样本：初始四项、第一次复测四项、最后针对否定与当前危险两项。10 次 ChatAgent 调用均完成；每次调用内部含辅助与主模型请求。初始否定样本出现过度危机推断，第一次提醒后仍有未陈述的压力推断，最后收紧证据提醒后未再追加危机话术；明确当前危险仍得到安全支持。最新追问仍有假定最近存在具体事件的措辞，不能视为所有语言细节已合格。
