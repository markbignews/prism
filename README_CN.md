# Prism / 棱镜

[English](README.md)

Prism 是我在做的一个 macOS 对话工具，用来整理复杂关系和个人叙事。它应该帮你把事情看清楚，而不是替你读心或替你做决定。

我希望它守住一条简单的原则：**结论不能比证据走得更远。**

## 我希望它怎么回答

- 把发生的事、你的理解和模型的推断分开。用户讲述的事情不等于经过独立核实的事实。
- 行为不能单独证明动机。联系、沉默或亲近都可能有不同解释；证据不够时就说明不够。
- 不把重复过的猜测当成新证据，也不把消息发送时间当成事情发生的时间。
- 可以讨论行为模式，但不把人贴成人格或临床标签；有反例时也要讲出来。
- 不盲目乐观，也不为了显得理性就只报坏消息。面对问题要诚实；保留事实的前提下，把希望放在仍然存在的可能性和自己能做的事上，不许诺结果。

这些是我对产品的要求，不是模型永远正确的保证。Prism 不能读心。**不知道的时候，就应该说不知道。**

## 今天修复了什么

- **输入长消息时不再把输入框撑成大块内容。** 输入区域会自然增长到约六行，之后可以在框内用滚轮或触控板查找和编辑；Return 发送，Shift+Return 换行。
- **生成回复时减少整窗卡顿。** 流式内容按批次刷新，把回复显示更新和整段历史渲染分开处理。
- **工具调用不再覆盖前几轮推理。** 每一轮工具调用的推理都会保留，最后一条“现在写回复”不会把前面的内容顶掉。
- **标题栏补上对话标题和简短说明。** 清楚标明内容由 AI 生成、仅供参考，请独立判断。
- **长 Key 不再撑大设置输入框。** 密钥框保持单行并可横向编辑；输入停止后自动验证，验证成功才允许完成首次设置。
- **把服务商报错说明白。** 将常见认证、限流、网络和服务错误翻译成可读的原因与处理办法，不直接把服务商的原始报错堆给用户。
- **模型列表可以自动或手动更新。** 设置会读取服务商的模型列表，Flash 模型优先显示；也可以手动刷新、填写模型 ID，并分别选择对话和辅助模型。
- **缩放和全屏时确认内容仍可操作。** 时间轴与人物确认卡片限制长说明的显示高度，让内容可以滚动，确认按钮始终留在卡片里。
- **需要补充关键信息时可以选择回答。** 模型可以发起一个紧凑追问，提供几个选项，也能手动输入；可以只选、只输入，或两者一起提交。回答会进入对话，再由模型继续处理。
- **各模式共用谨慎乐观的表达原则。** 判断仍然看证据，不因语气更温和就改变结论，也不因关键词直接套用固定危机回复。

## 当前版本

这个仓库目前只有 **Swift 版本**：SwiftUI 原生 macOS 应用。当前不提供或维护其他客户端版本。

应用按章节整理对话，保存人物与别名、叙事事件和情绪时间线，并引用相关消息作为分析依据。对话和结构化记录保存在本地 SQLite 数据库中。引用和记录能帮助回看依据，不代表模型解释一定正确。

## 运行

需要 macOS 15 或更高版本，以及带 macOS SDK 的 Swift 6 工具链。仓库里的应用包面向 Apple Silicon。

在仓库根目录运行：

```sh
cd "Prism/swift version"
swift run -c release Prism
```

首次启动时，在设置中填写 API Key、服务商端点和模型。默认使用 DeepSeek 端点与 `deepseek-flash`。Prism 不附带 API Key，也不包含离线模型。

首次设置会在停止输入后验证 Key，并读取模型列表；这个过程不发送聊天内容，也不生成模型回复。之后可以在设置里手动刷新模型列表。获取列表成功不代表每个模型都能正常对话，实际可用性仍由服务商账户和模型权限决定。

## 我会坚持的边界

发给模型的内容包括完成当前请求所需的对话、你主动添加的附件，以及相关分析或检索结果。请只发送你有权提供的信息。模型输出可能不完整或错误；Prism 不是心理治疗、诊断或急救服务。

当前 Swift 源码包含 **42 项自动回归测试**，覆盖安全判断、模型列表、输入与流式更新、工具调用推理保存、密钥验证和追问流程。自动测试不能代替真实服务商下的完整联调。
